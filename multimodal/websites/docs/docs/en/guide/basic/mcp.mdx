# MCP

Agent TARS is architecturally designed based on MCP. This section introduces how to connect MCP Servers in Agent TARS.

## Quick Start

We'll use [mcp-server-chart](https://github.com/antvis/mcp-server-chart) as an example to demonstrate how to customize MCP Servers in Agent TARS.

First, ensure you have created Agent TARS [Global Workspace](./workspace.mdx#global-workspace), then configure:

```ts
// agent-tars.config.ts
import type { AgentTARSAppConfig } from '@agent-tars/interface';

export default {
  // ...
  mcpServers: {
    'mcp-server-chart': {
      command: 'npx',
      args: ['-y', '@antv/mcp-server-chart'],
    },
  },
} satisfies AgentTARSAppConfig;
```

Let's use Agent TARS's recent optimization of CLI installation size as an example. Input the following prompt:

```

297M	0.1.12-beta.2/

 64M	0.1.12-beta.4/
```

## Remote MCP servers

For a remote server that uses Streamable HTTP, configure its MCP endpoint and
any authentication headers in your existing `agent-tars.config.ts`:

```ts
// agent-tars.config.ts
import type { AgentTARSAppConfig } from '@agent-tars/interface';

const apiKey = process.env.REMOTE_MCP_API_KEY?.trim();
if (!apiKey) {
  throw new Error('Set REMOTE_MCP_API_KEY before starting Agent TARS');
}

export default {
  // Keep your existing model and other settings.
  mcpServers: {
    // Keep your existing MCP servers here.
    research: {
      type: 'streamable-http',
      url: 'https://mcp.example.com/mcp',
      headers: {
        Authorization: `Bearer ${apiKey}`,
      },
    },
  },
} satisfies AgentTARSAppConfig;
```

Replace the example URL with your server's MCP endpoint and set
`REMOTE_MCP_API_KEY` in the environment of the process that starts Agent TARS.
This TypeScript example reads the environment explicitly; a literal string such
as `'Bearer ${REMOTE_MCP_API_KEY}'` does not read it for you. Keep credentials out
of URLs and committed configuration files.

Use `type: 'sse'` only for a server that explicitly provides the older HTTP+SSE
transport. Preserve your existing `mcpServers` entries when adding a server.
After starting a new session, verify that the expected tools were discovered;
a running session alone does not prove the remote connection succeeded.
